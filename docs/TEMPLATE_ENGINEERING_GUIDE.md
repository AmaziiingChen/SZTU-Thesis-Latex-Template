# 过程文档模板工程指南

## 1. 目的

本指南沉淀开题报告模板开发中已经由官方原件、压力样例和真实材料共同验证的工程方法，
用于指导任务书、中期检查、诚信声明和后续毕业论文模板开发。

目标不是让开发者“记住不要出错”，而是把格式要求转换为可测量的规格、共用组件和自动
回归门禁，使同类错误不能在下一个模板中重复出现。

## 2. 信息权威与职责分层

格式依据按以下顺序解释：

1. 当年学校发布的正式 Word、PDF 或表格原件；
2. `templates/<document>/spec/` 中由原件测量得到的文档规格；
3. `templates/common/` 中跨文档复用的语义模型、字体政策和工具；
4. Word、LaTeX 渲染器；
5. README、示例和历史生成件。

低层文件不得覆盖高层依据。历史优秀材料只用于真实内容压力测试，不是格式权威。

各类文件职责如下：

- `docs/TEMPLATE_ENGINEERING_GUIDE.md`：解释方法、原因和完整流程；
- `AGENTS.md`：保存执行任务时不得违反的简短硬约束；
- `templates/common/`：保存可执行、可复用的 Schema、排版令牌和测试工具；
- `templates/<document>/spec/`：保存某一种表单独有的测量值和字段映射；
- `templates/<document>/QA.md`：保存实际运行过的验收证据和未完成项；
- Skill：未来只负责组织上述流程，不复制尺寸和字体事实。

## 3. 固定开发流程

每一种新模板按以下顺序开发：

1. 冻结官方原件并记录来源、年份、页数和文件哈希；
2. 分别提取内容结构和视觉结构，不用 OCR 结果替代版式测量；
3. 编写文档专属 `spec/artifact.md` 和机器可读的 `spec/layout.json`；
4. 判断每条规则属于公共能力还是文档特例；
5. 先定义或复用 JSON Schema，再实现 Word 与 LaTeX 渲染；
6. 准备短、正常、长、版式压力和真实材料测试；
7. 运行结构、字体、边框、分页、中文字形和逐页视觉门禁；
8. 在关键里程碑由项目负责人使用 Word/WPS 人工验收；
9. 将每个新缺陷同时写回规格、实现、fixture 和自动断言；
10. 教师审核和 Windows 交叉验证完成后再冻结模板版本。

如果真实案例需要修改渲染器，说明发现了新的通用能力缺口。修复必须进入公共实现或文档
专属实现并补回归，禁止保留只适用于某一名学生的条件分支。

## 4. 表格、边框与分页

### 4.1 连续表格

- 从视觉上把一份连续表单视为一个整体外框。
- 如果实现上由多个组件组成，相邻组件必须共用相同左右坐标、线宽和连接位置。
- 相邻区域之间禁止出现空段落、段前段后距、LaTeX 垂直胶水或默认表格间距。
- 一条公共边线只能由一个组件负责绘制，避免叠画造成局部加粗。
- 标签区、正文区、参考文献区和签署区是否连续，以栅格图中的实际像素为准。
- 开题报告、任务书和中期检查的 LaTeX 连续表单统一引用
  `templates/common/latex/sztu-process-form.tex`；文档目录只能声明别名、宽度和专属高度，
  不得重新复制 `tcolorbox` 边框、内边距或紧密拼接实现。
- 公共皮肤消费的边框、水平内边距、固定/流式垂直内边距、正文尾部留白和标题后间距
  必须全部来自对应文档的 `spec/layout.json`，禁止在 `main.tex` 中写死。

### 4.2 分隔线

- 分隔线必须实际连接左右外框，不能只在 PDF 路径结构中存在。
- 线宽来自文档专属 `layout.json`，不同文档必须重新测量官方原件。
- 自动测试需要同时检查线段坐标、线宽和 180 DPI 以上的栅格墨迹。

### 4.3 跨页

- 内容自然增高和跨页，不通过缩小字号、压缩行距或减小页边距维持固定页数。
- 每个分页片段必须按照官方规则绘制本页顶部、底部和左右边界。
- 测试必须覆盖恰好在章节分隔线、长段落和长参考文献附近发生的分页。
- 人工签名和审核区域不得被长正文压缩；需要时整体移动到下一页。

## 5. 内容语义模型

### 5.1 字符级语义

上下标、粗体和斜体必须作为结构化 `runs` 保存：

```json
{
  "type": "paragraph",
  "runs": [
    {"text": "H"},
    {"text": "2", "script": "sub"},
    {"text": "O"},
    {"text": "2", "script": "sub"},
    {"text": "的相关研究"},
    {"text": "[1-4]", "script": "super"}
  ]
}
```

- 不使用 Unicode 上下标字符模拟排版；
- 从 Word、WPS 或网页粘贴的 Unicode 上下标兼容字符必须在公共规范化层
  转换为普通字符和显式 `script` 属性，禁止原样传入 Word 或 LaTeX 渲染器；
- `℃` 等依赖特定字体字形的兼容符号必须规范为可移植的语义文本（如 `°C`）；
- 不把 `H2O2`、`g-C3N4` 等基线数字当作可接受降级；
- 引用是否上标以原件为准，由数据显式表达；
- Word 与 LaTeX 消费同一份语义数据，不分别猜测格式。

### 5.2 块级语义

公共内容块至少区分：

- 普通段落；
- 有序列表；
- 无序列表；
- 参考文献条目；
- 后续需要时增加图片、表格、题注和公式块。

旧数据中连续的 `（1）（2）（3）` 可以由兼容层识别，但新模板优先使用显式列表结构，
避免靠换行和正则表达式推断作者意图。

## 6. 字体、字号与字重

- 中文字号名称统一由 `templates/common/typography/chinese-sizes.json` 映射为确定点值；
- 字体角色和允许的字体文件由公共字体政策定义；
- 文档专属 `layout.json` 只选择字体角色、字号名称和是否加粗；
- 字体族与字重是两个独立属性，“黑体”不自动等于“黑体加粗”；
- 缺少官方要求字体时停止生成，禁止静默回退到系统默认字体；
- 字体文件只从具有合法授权的本机环境读取，不提交商业字体；
- 渲染结果必须检查实际嵌入字体、实际字号和实际视觉字重，不能只检查源码命令存在。

当前公共字号映射包括小二 `18 pt`、小四 `12 pt`、五号 `10.5 pt`。具体文档是否使用这些
字号，仍以该文档官方原件和专属规格为准。

## 7. 段落、缩进和列表

- 正文独立段落默认首行缩进两个字符；五号正文对应 `21 pt`；
- “本课题研究内容如下”等引导句只要独立成段，也按正文规则缩进；
- 参考文献条目不使用正文首行缩进；
- 有序列表每项独立成段并具有明确层级缩进；
- 列表结束后的普通说明恢复正文缩进；
- 不使用空格、全角空格或手工 Tab 模拟段落缩进；
- 行距、段前距和段后距必须显式设置，不能依赖 Word 或 LaTeX 默认值。

## 8. 对齐与内边距

每个字段必须在文档规格中单独声明水平、垂直和换行策略：

- 表格标签通常水平、垂直居中；
- 姓名、学号等短值通常水平、垂直居中；
- 题目、学院等长值通常垂直居中、水平左对齐并保留内边距；
- 单行居中、多行左对齐的字段必须设置确定的切换规则；
- 多行左对齐时所有行保持相同左边界，禁止自动变为两端对齐；
- 单元格内容不得紧贴边框，内边距由文档规格给出。

测试既检查段落属性，也检查 PDF 中字符包围盒相对于单元格的实际几何位置。

## 9. 固定测试矩阵

每种模板至少包含：

1. 极短内容；
2. 正常内容；
3. 极长内容；
4. 顶部信息区压力样例；
5. 上标、下标、粗体、斜体和特殊符号；
6. 多级有序列表；
7. 超长参考文献或长条目；
8. 跨页边界样例；
9. 一份仅存于本地的真实历史材料；
10. Word/WPS 人工验收样例。

自动门禁至少包括：Schema、DOCX 重开、表格结构、字体字号、对齐、缩进、列表、边框、
分页、中文字形、完整文本和人工签署区保持为空。

## 10. 验收状态

以下状态必须分开记录：

1. 内容已提取；
2. 结构检查通过；
3. 中文字形有效；
4. 全页版式已检查；
5. Word/WPS 或目标 LaTeX 编译环境已验证；
6. 教师已审核。

生成文件成功不代表排版通过，LibreOffice 输出也不代表 Word/WPS 已验证。开发阶段优先
使用 LaTeX 快速迭代；Word 只生成 DOCX，由项目负责人在关键节点人工检查。

## 11. 隐私与发布

- `references/private/`、`output/**/private/` 和 `tmp/` 永不提交；
- 真实学生姓名、学号、签名和教师意见不得进入公开 fixture；
- 公开 fixture 使用虚构信息，但必须保留真实内容长度和结构压力；
- 官方材料只提交与排版直接相关且允许公开分发的部分；
- Skill、README 或示例不得把私人文件路径当作公开使用说明。

## 12. Skill 的建立条件

完成开题报告、任务书和中期检查后，如果同一流程在三个模板中均成立，再建立项目 Skill。
Skill 只负责定位官方原件、生成规格、调用公共组件、运行门禁和更新 QA，不保存具体尺寸，
也不复制本指南内容。仓库中的规格、代码和测试始终是事实来源。
