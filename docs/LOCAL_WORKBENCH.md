# 本地毕业设计文档工作台方案

## 决策

建设一个独立、开源、本地优先的桌面应用，暂定名为
`SZTU Graduation Docs Studio`。当前仓库继续维护深圳技术大学论文与过程文档的模板、
渲染器、版式规格和质量门禁；桌面应用放在独立仓库，通过版本化模板包消费这些能力。

两个仓库均按 GPL-3.0 开源。桌面应用不得移除上游作者、原始仓库、许可证和模板来源
说明。学校文件、商业字体和学生私人材料是否能够公开分发，必须逐项确认，不能因为应用
开源就自动视为可再分发。

完整实施顺序、任务编号和验收门禁见
[`LOCAL_WORKBENCH_DEVELOPMENT_CHECKLIST.md`](./LOCAL_WORKBENCH_DEVELOPMENT_CHECKLIST.md)。

## 产品目标

学生只需填写一次姓名、学号、专业、学院和指导教师等个人信息，再按文档类型填写特有
内容，即可导出已经套用当年正式模板的 Word、LaTeX 和 PDF 文件。应用负责结构化输入、
确定性排版、依赖检查和导出记录，不负责判断研究内容、数据、引用和学术结论是否真实。

## 工作台信息架构

工作台采用固定的三栏结构，不为不同文档类型重复设计页面。

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 文档工作台              已保存                         检查内容  导出 │
├──────────────┬───────────────────────────────┬───────────────────────┤
│ 学生档案     │ 当前文档                      │ 检查与导出            │
│              │                               │                       │
│ 开题报告     │ 基本信息                      │ 必填字段               │
│ 任务书       │ 选题意义及现状                │ 字体与环境             │
│ 中期检查     │ 研究内容                      │ 结构检查               │
│ 毕业论文     │ 研究方法与步骤                │                       │
│              │ 参考文献                      │ Word / LaTeX / PDF     │
│ 最近导出     │                               │ 最近导出记录           │
│ 设置         │                               │ 在 WPS/Word 中打开     │
└──────────────┴───────────────────────────────┴───────────────────────┘
```

### 左侧栏

- 当前学生档案及切换入口；
- 开题报告、任务书、中期检查、指导记录和毕业论文等文档目录；
- 最近导出；
- 模板、字体与应用设置。

### 中间编辑区

- 使用当前模板 Schema 自动生成字段；
- 基本信息默认来自学生档案，并允许对当前文档单独覆盖；
- 长正文按学校表格中的真实章节组织；
- 只提供模板支持的粗体、斜体、上下标和参考文献条目，不发展成通用富文本编辑器；
- 自动保存草稿，但清楚显示 `未保存`、`正在保存`、`已保存` 和 `保存失败`。

### 右侧检查与导出区

- 必填字段、字符长度、题目宽度和指导教师姓名格式检查；
- Word、LaTeX 和 PDF 的可用性及依赖预检；
- `结构检查通过`、`中文字形有效`、`逐页版式已检查`、`Word/WPS 已验证`
  四类状态分开显示；
- 导出后显示文件、模板版本、生成时间、数据哈希和检查结果；
- 提供 `在 WPS 中打开`、`在 Word 中打开` 和 `在文件夹中显示`。

## 技术架构

### 桌面端

- Electron；
- React + TypeScript + Vite；
- `shadcn/ui` 默认设计；
- Tailwind CSS 只使用 shadcn 默认主题变量及常规布局工具；
- Electron Renderer 保持 `contextIsolation: true`、`nodeIntegration: false`、
  `sandbox: true` 和 `webSecurity: true`。

### 本地后端

- Python 文档引擎；
- 通过 Electron 主进程管理的子进程和 JSONL IPC 通信，不在生产环境开放固定 HTTP
  端口；
- JSON Schema 负责输入合同；
- `python-docx` 负责 Word 模板填充；
- XeLaTeX 负责 LaTeX/PDF；
- SQLite 保存学生档案、草稿、模板版本、导出任务和检查回执；
- 字体、TeX Live、Word 和 WPS 都在本机预检，缺失时给出明确解决方法，不静默替换。

### 模板包

每种文档和年份是一个独立的版本化模板包。

```text
proposal-2026/
├── manifest.json
├── schema.json
├── official-template.docx
├── word/
├── latex/
├── fixtures/
├── qa-policy.json
└── NOTICE
```

`manifest.json` 至少记录模板 ID、学校、文档类型、适用年份、Schema 版本、渲染器版本、
正式来源摘要和文件哈希。桌面应用只面向模板包的稳定接口，不直接依赖模板仓库内部目录。

## 数据与 Agent 边界

- 学生信息和正文默认只保存在本机；
- 提供临时模式，关闭文档后删除本次输入和中间文件；
- 不采集遥测，后续如需错误报告必须单独征得用户同意；
- Agent 或 AI 只能生成符合 Schema 的候选字段与段落，不能直接修改 DOCX、OOXML、
  LaTeX 模板或签署区域；
- AI 生成内容必须先进入编辑区，由学生确认后才能导出；
- 学生签名、指导教师意见、学院意见及相应日期默认保持为空。

## 第一阶段 MVP

第一阶段只交付开题报告闭环：

1. 首次使用和本机环境检查；
2. 学生档案；
3. 开题报告结构化填写与草稿保存；
4. 字段和内容检查；
5. 导出 DOCX、LaTeX 源码和 PDF；
6. 导出回执与历史记录；
7. 在 WPS/Word 中打开；
8. macOS 和 Windows 安装包；
9. 四组已有 fixture 的自动回归；
10. Word、WPS、PDF 和中文字形门禁按独立状态验收。

MVP 不加入云账户、在线同步、通用 AI 写作、多人协作、学校管理后台和通用论文编辑器。

## 仓库与上游协作

### 模板仓库

- 保留 `upstream` 指向 `SZTU-ACM/SZTU-Thesis-Latex-Template`；
- 通用字体、编译、格式纠错和文档改进从最新 `upstream/master` 建立单主题分支；
- 开题报告等范围扩展先在 fork 完成，再通过 Issue 或 Discussion 确认上游是否接收；
- 私人材料、商业字体、未经确认可分发的学校文件和桌面应用代码不得混入上游 PR。

### 桌面应用仓库

- 使用独立 Git 历史和独立 Release；
- 模板仓库通过带版本和哈希的模板包 Release 向应用供给能力；
- 应用仓库记录模板来源仓库、提交和许可证；
- 模板修复回到模板仓库完成，应用只升级模板包版本，避免两份实现漂移。

## 前端实现约束

前端必须遵守仓库 `AGENTS.md` 的 `Local workbench frontend rules`：使用默认
`shadcn/ui`，禁止自研通用 UI 组件、定制视觉系统和未经批准的前端组件依赖。业务页面
只能组合 shadcn 组件，不能另建一套设计语言。
