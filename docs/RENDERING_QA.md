# 中文文档渲染与视觉检查规范

## 目的

避免出现“文字提取正常，但 Word/PDF 转图片后中文消失，仍继续依据空白图片判断版式”的错误。

本规范将文档检查拆成四个独立证据门：

1. **内容已读取**：文本层或文档结构中存在预期内容。
2. **渲染字形有效**：中文在页面图像中实际可见。
3. **全页版式已检查**：逐页检查文字、表格、分页、页眉页脚等。
4. **目标编辑器已验证**：Office 文件在 WPS/Word，LaTeX 文件在目标编译链与 PDF 阅读器中复核。

前一项通过不代表后一项通过。

## 强制流程

### 1. 先读内容，不先看缩略图

对 PDF 使用：

```bash
pdftotext -layout input.pdf -
```

对 DOCX 优先读取 OOXML/文档结构；对旧版 DOC 可先用 WPS/Word 导出 PDF，或使用 LibreOffice 做诊断性转换。

如果文本提取中存在大量中文，而页面截图只有数字、英文或表格线，应优先判断为字体或字形映射失败，不得判断为原文缺字。

### 2. 生成单页高分辨率图

```bash
mkdir -p /tmp/document-render
pdftocairo -png -r 180 input.pdf /tmp/document-render/page
```

- 文字检查不得低于 150 DPI。
- 首次检查必须打开单页原图；四页或多页联系表只能用于快速定位页面。

### 3. 执行中文渲染门禁

```bash
python3 scripts/validate_cjk_render.py input.pdf
```

脚本会读取 PDF 的文字坐标，找到包含中文的词语，再检查对应页面区域中是否存在实际笔画像素。

- 返回码 `0`：可以继续逐页视觉检查。
- 返回码 `1`：中文疑似未渲染，必须停止视觉结论并修复字体/渲染器。
- 返回码 `2`：依赖缺失、PDF 无可用文字层或输入无效，当前证据不足。

### 4. 逐页检查

字形门禁通过后，逐页以 100% 比例检查：

- 中文和英文是否都可见；
- 是否出现缺字方框、乱码或错误字体替换；
- 标题、正文、页眉页脚是否越界；
- 表格是否断裂、拥挤或跨页异常；
- 图片、公式、题注是否错位；
- 页码、目录、交叉引用是否稳定。

### 5. 目标编辑器复核

- `.doc/.docx`：WPS 或 Microsoft Word 为最终版式依据。
- `.tex`：macOS 使用 Texifier/TeX Live，Windows 使用 TeXstudio/TeX Live；最终检查生成的 PDF。
- LibreOffice 转换只算诊断证据，除非交付目标本身就是 LibreOffice。

## 失败时的处理

| 现象 | 结论 | 后续动作 |
| --- | --- | --- |
| 文本提取有中文，截图无中文 | 字体/渲染器失败 | 停止版式检查，检查字体注册或更换渲染器 |
| 文本提取也没有中文 | 文字层缺失、扫描件或编码异常 | 使用 OCR/文档结构读取，并明确证据边界 |
| 单页正常，联系表看不清 | 缩放导致不可读 | 回到单页高分辨率图检查 |
| 两个渲染器结果不同 | 渲染不确定 | 使用目标编辑器复核，不得选择性采用较好结果 |
| LibreOffice 正常，WPS/Word 异常 | 目标交付未通过 | 以 WPS/Word 结果为准继续修正 |

## 结果表述模板

只允许按实际通过的门禁表述：

- “已提取完整文字内容；尚未验证视觉版式。”
- “中文渲染门禁通过；正在逐页检查版式。”
- “已完成全页渲染检查；尚未在 WPS/Word 中验收。”
- “已在目标编辑器中完成最终验收。”

禁止把“成功导出 PDF”“生成了 PNG”“文本可提取”单独写成“版式检查通过”。
