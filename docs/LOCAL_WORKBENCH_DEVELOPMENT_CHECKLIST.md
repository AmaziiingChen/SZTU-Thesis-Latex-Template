# SZTU Graduation Docs Studio 完整开发清单

## 1. 文档用途

本清单用于直接驱动 `SZTU Graduation Docs Studio` 的开发、验收与发布。所有任务都应在
独立桌面应用仓库中实施；当前模板仓库只保留模板、渲染器、模板包源文件、质量门禁和
上游贡献。

清单状态规则：

- `[ ]`：尚未完成；
- `[x]`：任务产物、自动检查和所需人工证据均已完成；
- 不能因为页面存在、命令运行结束或文件成功生成就提前勾选；
- 若任务暂时阻塞，在对应任务下记录阻塞原因、负责人、下一动作和日期，不删除任务；
- 每个里程碑完成时，在应用仓库 `docs/evidence/` 保存一份验收记录。

## 2. 已确认决策

| 项目 | 决策 |
| --- | --- |
| 产品形态 | 本地优先的跨平台桌面工作台 |
| 暂定名称 | `SZTU Graduation Docs Studio` |
| 暂定本地路径 | `/Users/chen/SZTU-Graduation-Docs-Studio` |
| 开源许可 | GPL-3.0；保留上游作者、原始仓库、许可证和模板来源说明 |
| 桌面端 | Electron |
| 前端 | React + TypeScript + Vite |
| 组件 | 默认 `shadcn/ui`；禁止自研通用 UI 组件和自定义视觉系统 |
| 本地后端 | Python 子进程，通过版本化 JSONL IPC 与 Electron 主进程通信 |
| 本地存储 | SQLite |
| Word | `python-docx` 与官方 DOCX 底稿 |
| LaTeX/PDF | XeLaTeX |
| 数据合同 | JSON Schema |
| MVP | 只完成 2026 届开题报告闭环 |
| 隐私 | 默认不联网、不采集遥测、学生内容只保存在本机 |

当前开发机已观察到 Node.js `22.23.2`、npm `10.9.8`、pnpm `11.19.0`、Python
`3.14.4`、Git `2.50.1`、TeX Live 2025 和 latexmk `4.86a`。这些只是当前机器快照，
不是产品支持声明；新仓库必须通过工具链文件和锁文件固定最终采用的版本。

## 3. MVP 完成标准

只有以下条件全部满足，才可以把 MVP 标记为完成：

- 用户可在 macOS 和 Windows 安装并启动应用；
- 首次使用能够发现 Python 文档引擎、必需字体、XeLaTeX、Word 和 WPS 的真实状态；
- 用户可以创建学生档案和开题报告草稿，退出应用后恢复；
- 短、正常、长、版式压力四组 fixture 均能通过同一数据合同生成 DOCX、LaTeX 和 PDF；
- 导出结果包含模板版本、输入哈希、输出哈希、生成时间和逐项检查结果；
- 中文 PDF 通过中文字形门禁并完成规定的逐页检查；
- Word/WPS 验收状态与结构检查状态分开记录；
- macOS WPS/Word 和 Windows WPS/Word 的目标编辑器矩阵达到发布要求；
- 学生签名、指导教师意见、学院意见和相应日期不会被自动填写；
- 应用不使用自定义设计系统，不含商业字体、私人材料、密钥或未经确认可分发的学校文件；
- 自动测试、依赖审计、许可证清单、安装包校验和发布说明均已完成。

## 4. 里程碑与依赖

| 里程碑 | 结果 | 依赖 | 阻断后续 |
| --- | --- | --- | --- |
| M0 仓库与治理 | 独立开源仓库可协作 | 无 | 全部开发 |
| M1 安全桌面骨架 | Electron、React、shadcn、Python sidecar 可通信 | M0 | 数据与界面 |

| M3 本地数据闭环 | 档案、草稿、临时模式、恢复可用 | M2 | 工作台 |
| M4 工作台可用 | 三栏填写、检查、状态反馈完成 | M3 | 用户试用 |
| M5 导出闭环 | DOCX、LaTeX、PDF 与回执完成 | M2、M3、M4 | 文档验收 |
| M6 质量与跨平台 | 自动测试、中文门禁、Word/WPS 矩阵完成 | M5 | 正式发布 |

推荐关键路径：`M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7`。模板校准、Windows
