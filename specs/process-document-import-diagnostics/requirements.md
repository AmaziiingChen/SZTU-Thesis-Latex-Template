# 过程文档输入诊断需求

## 范围

本能力只检查开题报告、任务书和中期检查的输入批次，不改变三类模板的排版，也不处理
毕业论文模板。历史学生材料只作为本机输入；公开回归数据必须匿名且不得包含姓名、学号、
题目、正文、教师信息、原始文件名或绝对路径。

## 用户故事

1. 维护者需要在导入历史材料时发现三件套缺失、同类冲突和跨类别重复，避免把归档问题
   误当成模板缺陷。
2. 维护者需要把无文字层扫描件送入 OCR 或人工队列，而不是报告为“空文档”或“字形通过”。
3. 维护者需要隔离损坏、加密或不可解析文件，使单个异常文件不会中断整个批次。

## 验收标准

1. 当同一匿名对象缺少任一过程文档时，系统应为每个缺失类型产生
   `MISSING_DOCUMENT`，并保留其余文件的诊断结果。
2. 当同一匿名对象的同一文档类型出现多份文件时，系统应产生
   `SAME_TYPE_COLLISION`，不得静默选择其中一份。
3. 当不同文档类型具有相同文件哈希时，系统应产生
   `CROSS_TYPE_BYTE_DUPLICATE`。
4. 当 PDF 可解析但没有文字层且包含页面图像时，系统应标记为 `scan_only` 并产生
   `OCR_REQUIRED`，不得标记为内容为空或中文字形有效。
5. 当 PDF 不可解析、被密码保护或没有可判断的文字证据时，系统应分别标记并产生可操作
   的诊断代码，且继续处理批次中的其他文件。
6. 当生成公开或可提交的清单时，系统不得输出输入路径、原始文件名或原始对象键；只允许
   输出使用本机盐值生成的匿名 ID、文件哈希和结构统计。
7. 当输入记录包含毕业论文或未知类型时，系统应产生 `UNSUPPORTED_DOCUMENT_TYPE`，不得
   将其纳入三件套完整性判断。

## 非目标

- 不执行 OCR；
- 不判断历史文档是否符合官方排版；
- 不替代中文字形门禁、逐页检查或 Word/WPS 验收；
- 不修改或扩展毕业论文模板。
